# Emulsion store readiness, codebase audit

## Goal

The owner wants to sell Emulsion through the Mac App Store and the Microsoft Store. Emulsion is a local-first Lightroom replacement built on Tauri 2, Svelte and Rust, with ONNX models run by an `emulsion-ai` helper and an export-plugin hook. This audit is the codebase side of the plan. It lists everything in the repository that conflicts with Mac App Store rules (mandatory App Sandbox, signing of every nested binary, no self-update, no downloaded code, privacy) and Microsoft Store rules (packaged or unpackaged Win32, WebView2, no writes beside the exe, policies on external executables, privacy policy).

Read-only audit of `main` at `7ff4f4e` (branch `docs/progress-rfc-0038-status`). `git status --short` was identical at start and end. Nothing in the repository changed. The only file written is this report (plus a scratch iconset extraction in the same scratchpad folder).

Labels. **Measured** means I read it in the file or ran a command and saw it. **Inferred** means it follows from code I read plus platform behaviour I am confident of. **Guess** means a prediction, including every engineer-day size and every claim about store policy wording that I did not re-read this session.

Two corrections to the brief. There is no wgpu in the Rust tree. `Cargo.lock` has zero `wgpu` entries (measured), and the GPU pipeline is WebGPU inside the webview (`app/src/lib/gpu/pipelines.js`, `app/src/lib/gpuFallback.js`, measured). Face detection runs in the app process on `tract`, and only the helper links ONNX Runtime (`app/src-tauri/Cargo.toml:42-45`, measured).

## Questions the code could not answer

1. Is Emulsion sold under MIT, or as a paid closed product? `LICENSE` and PRD M8 disagree (RFC-0038 section 0). Counsel and the owner decide this, and it settles B5.
2. Does Tauri 2's bundler sign `externalBin` with its own entitlements, or with the app's? A test MAS-signed build and `codesign -d --entitlements -` on `Contents/MacOS/emulsion-ai` would answer it.
3. Does a sandboxed helper started with `com.apple.security.inherit` see folder grants the parent obtained after the spawn? A ten-line spike that resolves a bookmark in the parent and writes from the child would answer it.
4. Does the Windows helper link ONNX Runtime statically, or does `copy-dylibs` drop `onnxruntime.dll` beside it? Running `prepare-ai-helper.mjs` on the Windows CI runner and listing `target/release` would answer it.
5. Does the helper binary contain LibRaw or lensfun code? `nm` on the helper, or `cargo tree -e normal --bin emulsion-ai`, would answer it (RFC-0038 left this open).
6. What macOS version does the WebGPU path need in WKWebView, and is the CPU fallback good enough below it? A run on the oldest supported macOS would answer it.
7. Does LibRaw open files through a wide-char API on Windows, so paths over 260 characters and non-ASCII paths work? A test import from such a path on Windows would answer it.
8. Is the soft-proof or print custom ICC profile path stored across launches (`app/src-tauri/src/soft_proof.rs:38`, `printActions.js:17`)? If so it needs a bookmark too. Reading the print and soft-proof stores' persistence would answer it.
9. Does MSIX uninstall really delete the catalog, and would the owner rather submit an MSI? A test MSIX install and uninstall would answer the first. The owner answers the second.
10. Will OSM and Nominatim accept a commercial store app on their public servers? Their usage policies and, if needed, a paid provider's terms would answer it.
11. Do the model licences (SAM 2, LaMa, D-FINE, NAFNet, Real-ESRGAN, YuNet, SFace, face landmarks) allow redistribution in a paid store build? The `models/*_MODEL.md` files plus counsel would answer it. Not audited here.
