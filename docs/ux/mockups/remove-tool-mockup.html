What to expect from Remove
  • It paints in plausible background; it does not know what was really behind.
  • It can repeat texture. Look at 100 %.
  • Faces and text in the filled area are not reliable.
  • Large areas smear. If it looks wrong, use Heal on the same mark.
  • Runs on this computer; nothing is sent anywhere.

What this mock is for

  • One tool, plain name. "Remove", beside Clone and Heal. No prompt box, no "generative" wording.
  • The result is a proposal until Accept: Undo discards the stored patch; Heal is one click on the same mark, so the old tool is never taken away.
  • The mark is judged for the user. A mark that leaves a shadow or half a wire says so and offers to include it; a mark over 10 % of the photo says the result may be poor before it runs.
  • Each removed object is its own history entry (disable with the box, delete with ×), several marks go into one job.
  • Slice C2 prototype: variant A keeps the accepted result exactly; variant B re-runs when the photo is opened and the fill changes slightly. The study asks photographers which they expect and trust. "Patch file missing" shows the "needs regenerating" state of variant A.
  • Open question C (RFC §8): the Model selector shows the consent and download step if the model is not bundled.
