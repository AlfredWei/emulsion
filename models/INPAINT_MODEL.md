# Object-removal model: LaMa (fp32) as ONNX (RFC-0032, ADR-0010)

The app ships one inpainting file for the Remove tool, **bundled in the installer** beside the other models; the build fetches it and the app verifies it. There is no download dialog. A build whose edition leaves the removal model out (`models/bundled-models.json` `editions`, ADR-0012) does not bundle or seed it, and the Remove tool says "Remove is not included in this edition of Emulsion.", even if a valid copy is cached from an earlier build.

- **File**: `lama_fp32.onnx`
- **Source**: Hugging Face `Carve/LaMa-ONNX`, revision `c3c0c9e468934d62e79c329e35d82dd09ff8c444` (pinned in `models/bundled-models.json`)
- **Size**: 208,044,816 bytes
- **SHA-256**: `1faef5301d78db7dda502fe59966957ec4b79dd64e16f03ed96913c7a4eb68d6` (pinned in `models/bundled-models.json` and `app/src-tauri/src/inpaint_models.rs`; the app refuses any file that does not match). The same hash is what the repository publishes for that file at that revision.
- **What it is**: LaMa (Resolution-robust Large Mask Inpainting with Fourier Convolutions), the `big-lama` weights, exported to ONNX. Fixed 512 x 512 window: inputs `image` 1x3x512x512 (RGB, 0..1) and `mask` 1x1x512x512 (1 = fill); output 1x3x512x512 on the 0..255 scale, the pixels outside the mask coming back as given. Run on the ONNX Runtime CPU provider in the `emulsion-ai` helper (`bin/emulsion-ai/inpaint.rs`); `ai/inpaint_pipeline.rs` plans the window and builds the patch.
- **Licence**: Apache-2.0 for the code and the weights, per the model card of this repository and of the original `big-lama` card. The upstream `advimman/lama` `LICENSE` was read on 2026-11-14: it is the Apache-2.0 text, and its appendix names `Copyright [2021] Samsung Research`. The Apache-2.0 text is reproduced (the standard text, from the D-FINE repository's file) in `THIRD_PARTY_NOTICES.md`, which lists this model. Still not read: the ONNX conversion repository's own licence file.
- **Training data** (read 2026-11-14): "The best model (Places2, Places Challenge)"; the training setup also downloads an ADE20K ResNet50-dilated network "for _perceptual loss_" (https://github.com/advimman/lama). That network is used only during training and is not in the shipped file. **Terms, as one research run read them from archived copies; not re-opened since** (places2.csail.mit.edu refused connections on 2026-11-14): Places2, archived download page of 2021-02-20: "You will use the data only for non-commercial research and educational purposes" and "You will NOT distribute the above images"; today's page offers the legacy dataset "for research purposes" through a form; ADE20K (archived 2024): "Researcher shall use the Database only for non-commercial research and educational purposes". ADR-0010 §2 accepted Places2 with the terms unread, for a free MIT tool; those terms are now read and are non-commercial, which matters if the app is ever sold (RFC-0038, B5). Whether dataset terms reach the weights is a legal question this note does not answer. The `Carve/LaMa-ONNX` conversion adds no terms and does not mention training data. Not retrieved: Places2's current terms text; whether "Places Challenge" has its own terms.
- **Measured** (RFC-0032 §9): closest to the original in 46 of 60 hole cases against MI-GAN and a PatchMatch baseline; 2.3 s per removal on an M1 Pro CPU at its native window; bit-identical between runs on one machine and provider, texture-level differences between CPU and CoreML (§10).

## In a development build (`make dev`)

The 208 MB file is not committed. Copy it to `models/lama_fp32.onnx` (it is git-ignored; the SHA-256 above must match, or `node app/scripts/fetch-bundled-models.mjs --from <dir>` fetches or copies it). A debug build seeds the app's model cache from the checkout's `models/` at startup and when the Remove tool checks availability, **after** any `target/debug/models` a bundled build left behind (before 2026-11-08 that folder hid this one). Restart the app after adding the file.
